# 0001. Inbound Recovery Hybrid

## Status
accepted

## Context
Входящие и MID находятся только в памяти, а исходящая очередь не восстанавливает потерянный вопрос. Пользователь утвердил гибрид webhook, постоянного журнала и Conversations API. Альтернатива: один опрос API; она не сохраняет полный webhook-контекст рекламы и ограничена доступностью двадцати последних сообщений.

## Decision
Использовать существующую SQLite для постоянного журнала входящих и явных результатов; сохранять webhook до HTTP 200. Дополнить приём ограниченной сверкой Conversations API после запуска и каждые 120 секунд. Отдельно учитывать технические повторы, один пересмотр молчаливой передачи, готовые исходящие части и неопределённую доставку. Основной приём через webhook сохраняется. Подробный протокол будет утверждён на фазе Design до runtime-реализации.

## Consequences
Плюс: переживаем перезапуск, обнаруживаем пропущенные уведомления и не принимаем известный MID за завершённую обработку. Минус: нужны транзакции результатов, контроль авторства исходящих и ограниченный бюджет API. Содержимое старше двадцати последних сообщений и полный рекламный контекст через API не гарантируются; Message.referral недоступен в живом probe. Production-доступ и совпадение ID ещё требуют проверки. Новый сервер, Redis и изменение прав Meta не требуются для выбранного прототипа.
