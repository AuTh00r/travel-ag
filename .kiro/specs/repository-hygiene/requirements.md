# Временные стенды в рабочем каталоге

Micro Spec, 2026-10-20, до изменения конфигурации.

Intent: исключить генерируемые корневые каталоги `.tmp-*` из Git/Ruff.
Read-only аудит обнаружил20355 неотслеживаемых файлов временных проверок;
`ruff check .` читает фиктивные rollback/runtime.py и выдаёт68 ошибок.
Эти каталоги не содержат отслеживаемых Git-файлов. Цель — вернуть проверку
исходников проекта без обхода правил для `src/`, `tests/` и `scripts/`.

Boundaries: только правило `/.tmp-*/` в `.gitignore`. Файлы не удаляются;
не менять Ruff rules, исходники, историю Git, index, remote и production.
Новые рабочие модули остаются видимыми до отдельного stage/commit/push.

Acceptance: `git check-ignore` подтверждает временный fixture; реальные
`src/services/inbound_recovery.py` и `tests/test_recovery_scan_budget.py`
не игнорируются; `ruff check .` завершается exit0; `git diff --check` чист.
Статус: выполнено локально. `ruff check .` до правки68 ошибок в13 временных
стендах, после exit0/All checks passed. `git check-ignore` подтверждает fixture;
исходник и тест не игнорируются, diff check exit0. Файлы сохранены.

## Уборка перед переносом, 2026-11-04

**Type:** Micro Spec / repository housekeeping, менее одного дня.

### Intent (What + Why)

Убрать из рабочей папки подтверждённые генерируемые стенды и кеши, устранить
устаревшие активные инструкции и дать один вход в актуальную документацию.
Разделить текущие локальные изменения, последний известный серверный release
и GitHub, чтобы после переноса они не воспринимались как один снимок.

### Boundaries (Files + Out-of-scope)

**Files:** `.gitignore`, новый `README.md`, `PROJECT_CONTEXT.md`,
`docs/SETUP.md`, `docs/DEPLOY.md`, `docs/ENV-SETUP.md`, `docs/MCP-SETUP.md`,
`docs/DEVELOPMENT.md`, `docs/ARCHITECTURE.md`, `docs/archive/README.md`,
`docs/archive/PROJECT_CONTEXT-2026-08-04.md`,
проектный `.agents/skills/travel-bot-dev/SKILL.md`;
проверенные неотслеживаемые `.tmp-*`, `.tmp_docx_qa`, кеши Python/pytest/Ruff.
Исторический контекст сохраняется в явно помеченном `docs/archive/`.
Перед правками сохранить исходники документов; временные каталоги переместить
в отдельный внешний архив с манифестом и проверкой содержимого.

**Out-of-scope:** бизнес-логика `src/`, тесты, рабочие скрипты, `.venv`, `.env`,
credentials, клиентские БД, каталог туров, Git index/history/remote,
production и деплой. Не удалять неподтверждённые бизнес-данные; не выдавать
локальный N42 за выложенный код. `.claude` и исторические runtime/spec evidence
сохраняются. Коммиты и push не входят в запрос.

### How

Сверить инвентарь и документы с кодом и существующими спеками; собрать
резервный манифест; убрать проверенный мусор обратимым перемещением;
исправить инструкции минимальными правками; проверить ссылки, ignore-правила,
контрольные суммы защищённых файлов и существующие offline-проверки.

### Acceptance

1. У перемещаемых каталогов нет Git-tracked файлов; исходный и архивный
   наборы относительных путей, размеров и SHA-256 совпадают.
2. Код, тесты, рабочие данные/секреты и Git index не меняются; подтверждение
   исходным/итоговым манифестом. Производные `__pycache__` в хеши кода не входят.
3. Активные инструкции не предлагают массовый сброс клиентских данных,
   не называют отсутствующий Docker-config рабочим и не обещают, что
   `git clone` содержит последний source-only release.
4. Есть README-навигация и явно помеченный исторический контекст; текущие
   инструкции различают серверный quiet-window release и локальный N42.
5. `.env`, резервные env-файлы и производные файлы игнорируются; реальные
   `src/` и `tests/` остаются видимыми Git. Секреты не выводятся в отчёт.
6. Markdown-ссылки в изменённых активных документах, синтаксис применимых
   команд, Ruff и `git diff --check` проверены; результаты зафиксированы.

### Upgrade-гейт

Изменения поведения бота, формата данных и механизма деплоя оформлять отдельной
спекой. Эта уборка исправляет описание и размещение существующих артефактов.

**Статус:** уборка выполнена локально 2026-11-04; на момент её завершения commit
и deployment не выполнялись. Последующая подготовка публичного commit описана ниже.

### Факт и проверки

В приватный архив вне репозитория перемещены 249 неотслеживаемых каталогов:
237 корневых `.tmp-*`, `.tmp_docx_qa`, три корневых кеша и восемь `__pycache__`
в исходниках/тестах/скриптах. Проверено 34953 файла, 609479760 байт:
относительные пути, размеры и SHA-256 до и после совпали. Отдельно сохранён
повторно созданный Ruff-кеш: 5 файлов, 4893 байта. Ни один каталог не содержал
Git-tracked файлов. Различия Windows-прав обработаны двумя штатными контекстами
исполнения; ACL не менялись, недоступные каталоги не удалялись вслепую.

Исходные документы сохранены в том же приватном архиве. Добавлен README,
августовский PROJECT_CONTEXT сохранён в docs/archive с исторической пометкой;
в корне оставлен актуальный указатель. Исправлены SETUP/DEPLOY/ENV/MCP,
навигация DEVELOPMENT/ARCHITECTURE и проектный skill. Убраны рецепты удаления
клиентской БД и массового reset, отсутствующие booking/Sheets API, старые
фиксированные числа тестов и обещание готового Docker-развёртывания.

Контрольный список защищённых файлов: 130 SHA-256 совпали (код, тесты,
рабочие данные, Git index и другие рабочие файлы); четыре приватных файла
проверены по размеру и LastWriteTimeUtc без чтения секретов — без изменений.
Приватные манифесты в Git не добавляются.

QA: полный native Windows pytest — 1815 PASS, 8 прежних warnings, 99.09 с;
Ruff src/tests/scripts PASS; micro-spec validator PASS; ignore-проверки PASS.
Первый sandbox pytest дал 1812 PASS/3 native image decode FAIL; те же три
теста вне sandbox — 3 PASS, затем полный прогон — 1815 PASS без skip/ослабления
проверок. Бизнес-код, тесты и данные для получения green не изменялись.
Локальные Markdown-ссылки и diff whitespace проверены отдельно.

### Предкоммитная проверка публичного снимка

До разрешённого владельцем commit/push проверяются все prospective файлы.
Дополнительные редакционные границы: `.env.example` — убрать опубликованное
токеноподобное значение DuckDNS, оставить пустой шаблон;
`runtime/bialystok-old-denials.md` — сохранить технический вывод без имён,
идентификаторов и дословных цитат двух клиентов. Приватные оригиналы
сохраняются вне репозитория до редактуры, значения не выводятся в отчёт.
Функциональные исходники и тесты не меняются. Ротация ключа и переписывание
истории Git не входят в commit/push и требуют отдельного действия владельца.

Acceptance: в staged-шаблоне DuckDNS пуст; в staged-заметке нет исходных
персональных полей; данные и временные каталоги исключены из commit.

Предкоммитный `git diff --cached --check` также выявил лишнюю пустую строку
в конце 11 ранее неотслеживаемых файлов: четыре media-understanding spec,
три runtime-заметки и четыре Python-теста. Нормализуется только конец файла,
без изменения Python-токенов или содержания документов; оригиналы сохранены
в приватной копии `eof-before`. После этого тот же staged-check повторяется.

Факт: staged-шаблон DuckDNS пуст; обезличенная staged-заметка проверена
независимо; среди 212 путей первого коммита нет приватных файлов и БД.
`git diff --cached --check` после нормализации PASS; AST четырёх Python-тестов
совпадает с оригиналами, Ruff PASS. Старое токеноподобное значение остаётся
в ранее опубликованной истории Git: если ключ действующий, владелец должен
отдельно сменить его. История и ключи в рамках этой работы не переписываются.
