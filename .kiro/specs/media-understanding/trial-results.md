## Расчёт стоимости и открытый выбор отбора — 2026-10-08

Автоматическое сокращение 17 кадров до меньшего количества в опыте не реализовано и не проверено. Выбор первого кадра был ручным. Это нельзя выдавать за готовый алгоритм отбора.

Официальный текущий тариф `deepseek-flash` проверен: [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/). Без попадания в кэш: вход $0,15 за миллион токенов вне пика / $0,30 в пик; выход $0,60 / $1,20 соответственно. Денежные значения ниже — расчёт по тарифу, не подтверждённое списание с аккаунта.

Официальный [калькулятор изображений](https://api-docs.deepseek.com/quick_start/token_usage/) прочитан прямым HTTP-запросом; проверен его текущий код `1e0da2c4.24c3fb4b.js` на домене документации. Для 720×1280 он даёт оценку 591 токен изображения: ceil(1280/14)=92, ceil(720/14)=52; после downsample 3 — 31×18; токены 31×(18+1)+2=591. Документация указывает, что расчёт приблизительный и usage API — источник фактического количества. При нескольких изображениях каждое тарифицируется отдельно; [Vision](https://api-docs.deepseek.com/guides/vision/) указывает верхнюю границу 1024 токена на изображение.

Для сравнения используется фактическая база одного запроса: 773 входных, 183 выходных токена. Каждому дополнительному кадру приписаны оценочные 591 токен изображения и 12 токенов подписи времени. Число выходных токенов для всех вариантов условно сохранено равным 183; реальные ответы могут отличаться.

При 1000 разных историй по 17 кадров оценка составляет около $1,67 вне пика / $3,35 в пик только за такой разбор кадров. Каталог, история диалога, дополнительные AI-запросы, сервер и возможный локальный OCR в этот расчёт не входят. Новых платных вызовов для расчёта не было.

Предложение, пока не утверждённое решение: для первой версии разбирать всю регулярную выборку каждые 1,5 секунды и сохранять извлечённый контекст по ID истории, чтобы повторные клиентские вопросы не требовали повторного разбора. Это проще, чем гарантировать отбор одного кадра без потери новых надписей. Для отбора по тексту потребуются локальный OCR всех кандидатов, группировка по совпадающим надписям с сохранением различий в числах/датах/ценах, выбор чёткого представителя группы и сохранение неуверенно прочитанных кадров. Визуальные сцены тоже могут быть важны: совпадение надписей само по себе не доказывает равенство всей информации. Такой отбор требует отдельной проверки качества и не обещает универсального сокращения до одного кадра.
