# Проверка доступности точного видео истории

Дата: 2026-10-08. Аккаунт: @sundita.travel. API: Meta Graph API v25.0 с существующей конфигурацией проекта. Все запросы read-only; исходники приложения, настройки аккаунта и production не изменялись. Токен и подписанные CDN-ссылки не сохранены в артефактах. Видео прочитано в оперативную память, на диск не записывалось; платных вызовов распознавания не было.

## Проверенные факты

1. Запрос `me?fields=id,instagram_business_account{id}` подтвердил ожидаемую страницу и связанный Instagram business account.
2. `/{ig-user-id}/stories?fields=id,media_type,media_url,thumbnail_url,timestamp&limit=25` вернул три активные истории: две VIDEO и одну IMAGE. У обеих VIDEO присутствуют разные `media_url` и `thumbnail_url`.
3. GET `/{story-id}?fields=id,media_type,media_url,thumbnail_url,timestamp` успешно вернул каждую из двух VIDEO по её конкретному идентификатору.
4. Частичное чтение MP4 позволило проверить контейнер, длительность и наличие видео-/аудиодорожек. Полное чтение каждой соответствующей `media_url` вернуло HTTP 200 и `video/mp4`. Размер совпал с объявленным полным размером; разбор верхних MP4-блоков завершился точно на конце файла.

## Что это доказывает и чего ещё не хватает

Доказано получение полного опубликованного видеофайла двух конкретных активных историй собственного аккаунта, включая аудиодорожку. Это не превью. Файл, который отдаёт Instagram, может быть перекодированной версией загрузки; совпадение с исходным файлом камеры не проверялось.

НЕ проверены: декодирование кадров, различимость речи, совпадение наложенных элементов с просмотром в приложении, реальные ответы клиентов, истёкшие истории, видео с лицензированной музыкой и доступность любого другого видео. Наличие аудиодорожки не доказывает наличие речи. Проверка двух историй не гарантирует универсальную доступность.

Последний незакрытый участок: получить реальное событие ответа клиента, сохранить безопасные диагностические поля `message.reply_to.story.id`, тип события и `mid`, затем проверить получение полного видео по именно этому ID. Текущий обработчик не сохраняет идентификатор/ссылку истории в нормализованном сообщении, поэтому существующего клиентского текста и обычных логов недостаточно для доказательства всей цепочки.

Если API не отдаёт файл или история уже недоступна, необходимо уточнение у клиента либо передача менеджеру. Подмена приблизительным совпадением тура/ролика запрещена выбранным пользователем условием.

## Источники и ограничения ресёрча

- Официальный Meta Python SDK: [IGMedia](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/igmedia.py) определяет `media_url` и `thumbnail_url`, чтение объекта по ID. Основное доказательство доступности здесь — фактические ответы API на подключённом аккаунте.
- [Опубликованный реальный webhook в issue restfb](https://github.com/restfb/restfb/issues/1246) показывает структуру `message.reply_to.story.id/url`; событие 2022 года, не замена проверке нашего текущего аккаунта.
- [CM.com: Instagram inbound](https://developers.cm.com/messaging/docs/instagram-messaging-inbound) описывает metadata истории в ответах. Документация интегратора, не первичная документация Meta и не гарантия содержимого полного видео.
- [Официальная документация Meta Story Reply](https://developers.facebook.com/docs/messenger-platform/instagram/features/story-reply/) и [Stories](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/stories) не прочитаны: веб-инструмент получил ошибку доступа/429. Это ограничение доступа к документации, а не доказательство отсутствия возможности API.

## Статус выбора

Ранний диагностический интервал извлечения кадров: 1,5 секунды (2026-10-08). Для проверенных роликов при выборке от `t = 0` это 17 и 6 кадров соответственно. После проверок пользователь выбрал для будущей интеграции 10 равномерных кадров всего видео с detail original, отправленных одним запросом вместе с вопросом клиента. Качество понимания одного кадра проверено на двух объявлениях; полный production-запрос с 10 кадрами ещё не выполнен.

Пользователь выбрал направление «точное видео → кадры → DeepSeek → ответ» при условии подтверждения точного файла; последующим уточнением 2026-10-08 исключил расшифровку звука видео. Проверенное наличие аудиодорожек выше остаётся фактом исследования, но не требованием обработки. Требования пока draft; дизайн, задачи и реализация не выполнялись. Проверка полного файла по собственному story ID завершена; проверка реального ответа клиента и сквозное распознавание остаются открытыми.

Отдельный локальный опыт завершён: из первой истории извлечены 17 кадров через 1,5 секунды; по дополнительному согласию пользователя в DeepSeek отправлен только первый кадр. HTTP 200, видимые даты/маршрут/условие про визы прочитаны верно. Полные результаты и пределы вывода — `trial-results.md`. Реальная связь клиентского webhook с этим видео по-прежнему не проверена.
