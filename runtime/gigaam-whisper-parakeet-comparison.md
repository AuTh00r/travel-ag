# GigaAM v3 E2E RNN-T: локальное сравнение, 2026-10-10

GigaAM успешно распознаёт голосовые на сервере проекта без GPU. На двух собственных записях он быстрее ранее измеренных Parakeet Q8 и Whisper large-v3-turbo; вопрос про маму и программу передал точнее обоих на наблюдаемых фразах. Синтетический контроль показал правильные телефон, дату, цену и названия туров. Это ограниченный опыт с community ONNX-конверсией, не универсальная оценка русской речи и не включение голосовых в production.

## Установка и воспроизводимость

Испытан `GigaAM-v3-e2e-rnnt`: ONNX FP32-конверсия `istupakov/gigaam-v3-onnx` официальной модели `ai-sage/GigaAM-v3`. Это сторонний экспорт, не официальный бинарный артефакт Сбера; результаты относятся к этой конкретной реализации. Community model card и exporter заявляют происхождение, но отдельная побитовая эквивалентность с официальным PyTorch checkpoint здесь не доказывалась.

HF revision зафиксирован: `322c3b29492673eb7d0b434bfa9dfb8653e34d02`. Пять файлов скачаны из этого snapshot, LFS SHA256/размер или Git blob SHA1 сверены с метаданными. Encoder SHA256: `cd60b3764a832e8560ae6d3ad0b10adc1a42ffae412b9476f25620aae4f4a508`. Всего файлов модели 892 410 829 байт; загрузка примерно 82,7 с на конкретной сети опыта.

Отдельное окружение: onnx-asr 0.12.0, ONNX Runtime 1.23.2, NumPy 2.2.6; pip check PASS. Только готовые PyPI wheels, без PyTorch/Transformers/системного FFmpeg/PATH/production-зависимостей. ONNX загружен из существующей проверенной папки offline, без `trust_remote_code` или выполнения кода из модельного репозитория. Размер отдельного runtime 196 866 886 байт. Это логические размеры файлов, не выделенные дисковые блоки и не вся папка pip-cache.

Сервер: Intel i5-13400, 16 логических процессоров, 15,77 GiB RAM. ONNX Runtime при импорте вывел `Unsupported Windows version (2019server)`: все испытания на этом сервере выполнены успешно, но это не подтверждение официальной поддержки Windows Server 2019 поставщиком. Перед постоянной эксплуатацией нужно учесть совместимость выбранного runtime с ОС; предупреждение не скрывалось.

## Аудио и настройки

Baseline полностью тот же, что в [предыдущем сравнении](parakeet-whisper-comparison.md): собственная запись про Варшаву 21,4386875 с, настоящее голосовое Instagram про Италию 6,912 с, 3 с цифровой тишины. Общий PCM 16 кГц, mono, int16, хеши совпали. Из него для ONNX/Whisper получен float32 делением на 32768; Parakeet получает WAV с теми же samples. Первое распознавание плюс два повторных на каждом образце, модели загружаются один раз; входные WAV декодируются до таймера.

Для GigaAM заданы CPUExecutionProvider, 2 intra-op/1 inter-op threads, ORT_SEQUENTIAL, NumPy-preprocessor, один worker. Переменные OMP/OpenBLAS/MKL ограничены двумя потоками до импорта библиотек. Greedy RNN-T decoding; precision FP32, не INT8. Parakeet использует Q8_0 native HTTP, Whisper — CPU INT8/beam5/VAD. Это сравнение реальных кандидатов с разными алгоритмами и форматами весов.

В первом запуске стандартный ONNX spinning был включён. Encoder/decoder/joint имеют отдельные session pools, и заданные два intra-op threads не ограничивают весь процесс двумя потоками. Измеренная средняя доля полной CPU-ёмкости: 15,96% на длинной записи и 25,20% на короткой. Во втором запуске, сохранив первые отчёты, отключены `session.intra_op.allow_spinning` и `session.inter_op.allow_spinning`. Нагрузка снизилась примерно до 12,4%, время увеличилось; текст во всех пяти случаях остался побуквенно таким же. Это эмпирическое сравнение двух настроек, не доказательство точного числа одновременно работающих потоков.

Постоянная память здесь означает среднее двух снимков WorkingSet после длинной записи, не среднюю память во время STT.

Результаты Parakeet/Whisper baseline взяты из сохранённого предыдущего опыта, не из одновременно выполненных замеров на одинаковой фоновой нагрузке.

Все baseline CPU-счётчики — Windows kernel+user, включая native threads; процент равен 100×CPU_seconds/wall_seconds/16. В таблице среднее двух процентов, не system-wide загрузка или мгновенный пик. No-spin повторы заметно различаются по времени: среднее 2,72 с не является гарантированным SLA.

Отключение spinning снижает интенсивность CPU, но в этом опыте не экономит суммарную процессорную работу: CPU-секунды выросли примерно на 18% для двух собственных голосовых и на 38% для синтетического контроля. Поэтому default лучше по задержке и измеренным CPU-секундам на запрос, no-spin — по доле одновременно занятой CPU-ёмкости. Это следует учитывать при выборе режима, а не называть no-spin общим снижением расхода CPU.

Для полноты прежние small/medium на том же baseline: small6,060с/4,198с/395,92MiB после Варшавы/693,21MiB пик; medium16,563с/12,382с/920,05MiB/1741,00MiB. Модельные файлы486MB/1531MB. ## Качество и вывод

GigaAM передал начало «тур в Варшаву», фразу «не быть с программой» и окончание «вот такой вопрос интересует». Parakeet пропустил «с»; turbo сохранил эту фразу, но окончание передал «вот такого просто интересует». В коротком голосовом все модели сохранили вопрос про туры в Италию.

В синтетическом контроле GigaAM сохранил все перечисленные поля, включая телефон сразу с `+` и цифрами. Parakeet сохранил цифры телефона, дату/дни/цену и два других тура, но выдал «Поздном» вместо «Познань»; номер оформил «плюс 375-291234567». Turbo сохранил все проверяемые поля и «Познань», номер оформил «Плюс 375-29-1234567». Различие форматирования номера нельзя автоматически считать потерей цифр. У GigaAM были мелкие отличия вне проверяемых полей («обращения» вместо «обращение»), поэтому сохранность полей не означает идеальный текст.

У двух вариантов GigaAM все три повтора каждого образца дали одинаковый текст, их результаты между настройками совпали. Цифровая тишина не породила текста. Это не гарантия отсутствия галлюцинаций на шуме. Нет полного пословного человеческого эталона для двух естественных голосовых — WER/процент точности для них не вычислялись. Номера/даты проверены только на синтетическом голосе, не на диктовке клиента; шум, акценты, длинная естественная речь, очередь нескольких клиентов и GPU остаются непроверенными.

На повторе собственного аудио GigaAM сохранил обе копии baseline-текста полностью. У turbo во второй копии пропало «с» перед «программой», которого он не терял на исходном коротком файле; разбиение может влиять на результат. Parakeet пропускал «с» в обеих копиях. Контроль не доказывает, что выбранный простой chunk helper безопасен для произвольных непрерывных сообщений.

Предварительный кандидат — GigaAM no-spin: ниже средняя CPU-интенсивность при всё ещё более короткой задержке, чем Parakeet, и лучшей передаче наблюдаемых фраз. Компромисс: RAM после основного образца примерно на 21% больше Parakeet и на 4% больше turbo, отдельный Python/ONNX runtime и предупреждение об ОС. Окончательная production-интеграция/выбор модели не выполнены.

## Последующее решение владельца и очистка (2026-10-10)

После сравнения владелец выбрал GigaAM. Whisper small/medium/turbo и Parakeet удалены с сервера вместе с отдельными runtimes/models/helpers и подтверждёнными install-cache записями; historical evidence сохранены локально.
