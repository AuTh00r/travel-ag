# Parakeet v3 Q8 и Whisper: испытание на сервере, 2026-10-10

Parakeet работает на нашем Windows-сервере без GPU. На двух собственных записях владельца он быстрее Whisper turbo в 3,30 и 7,49 раза. Смысл обоих вопросов сохранён, но в длинной записи Parakeet пропустил предлог, который turbo передал правильно. Рекомендация по этому ограниченному опыту: Parakeet — основной кандидат для голосовых бота; production-интеграция ещё не выполнена.

## Условия и границы сравнения

Сервер: Intel Core i5-13400, 16 логических процессоров, 15,77 GiB физической RAM, Windows. GPU не использовался. Каждый движок работал отдельно, с двумя потоками распознавания и одним запросом одновременно. Это не жёсткое ограничение всех потоков процесса или измерение общей загрузки Windows.

Движки: официальный NVIDIA NeMo-Speech.cpp 0.2.0 Windows x86_64 CPU с Parakeet TDT 0.6B v3 Q8_0 GGUF; faster-whisper 1.2.1 / CTranslate2 4.8.2 / PyAV 16.1.0 с small, medium и large-v3-turbo, CPU INT8, beam=5, language=ru, VAD включён, condition_on_previous_text=False. У Parakeet VAD в этом опыте отсутствовал.

Два исходных файла владельца: M4A о поездке в Варшаву и посещении мамы (21,439 с) и настоящее голосовое из Instagram о турах в Италию (6,912 с; AAC в MP4). Контроль — 3 с цифровой тишины. Для всех движков использован один и тот же декодированный PCM: 16 кГц, mono, int16. На каждый файл — первый проход и два повторных прохода, всего 36 распознаваний. После второго файла движок уже прогрет: его «первый проход» не означает холодный запуск процесса.

Сравниваются реальные настройки кандидатов, а не математически одинаковые алгоритмы. Parakeet измеряется через локальный HTTP-сервер 127.0.0.1 с разбором WAV; Whisper получает заранее декодированный массив напрямую. Для Whisper таймер охватывает полное потребление ленивого генератора результатов. Время модели ниже не включает скачивание голосового, первоначальное декодирование исходника, пятисекундный сбор сообщений, DeepSeek и доставку ответа. Первоначальное преобразование двух исходников в общий WAV заняло соответственно 0,0837 и 0,0430 с. Полная задержка ответа бота и длительность скачивания в этом сравнении не измерялись.

* Области замера загрузки различаются: Parakeet — запуск native-процесса до ответа readiness без прогрева; Whisper — инициализация модели без запуска Python/импортов. ОС-кэш диска не очищался; подгрузка страниц Parakeet может происходить при первом распознавании. Эти цифры не доказывают преимущество по полному холодному старту.

** Parakeet runtime — распакованные exe/DLL; Whisper runtime — существующее отдельное Python-окружение с общими зависимостями для всех трёх моделей. Подготовка аудио Parakeet также использовала этот PyAV; самостоятельная production-интеграция всё равно потребует декодер. Логические размеры файлов не равны занятым NTFS-блокам или полной cache-папке с возможными дубликатами. Runtime Parakeet скачан за 1,276 с, веса — за 63,513 с; это конкретная скорость сети опыта, не гарантия установки.

RAM получена из Windows PeakWorkingSet/WorkingSet всего процесса распознавания. Whisper включает Python и временные буферы загрузки, native Parakeet не включает управляющий Python HTTP-клиент. Поэтому это сравнение измеренных процессов, а не чистой памяти весов или полной памяти готового приложения.

Parakeet против turbo: время длинной записи меньше на 69,73%, короткой — на 86,64%; CPU-секунд длинной записи меньше на 70,26%. При этом средняя интенсивность CPU во время распознавания похожая — примерно два занятых логических процессора. Пиковая RAM ниже на 54,43%, постоянная после длинной записи — на 13,61%. Эти два показателя нельзя объединять в «памяти меньше на 54%».

CPU% вычислен из времени kernel+user процесса: 100 × CPU-секунды / реальное время / 16. В таблице среднее арифметическое процентов двух прогонов, не взвешенное по длительности; отличие здесь менее 0,004 процентного пункта. Это средняя доля полной логической CPU-ёмкости в интервале STT, не загрузка всего сервера и не мгновенный пик. Для VAD-результатов тишины по 4–5 мс CPU-счётчики и округление слишком грубы для содержательного сравнения CPU%; нулевой измеренный прирост CPU не означает нулевую стоимость работы.

## Качество на собственных записях

| Движок | Длинная запись: наблюдаемое отличие |
| --- | --- |
| Parakeet | Правильно «тур в Варшаву», мама, желание навестить её отдельно от программы. Фраза «не быть программой»: пропущено «с». Конец «Вот такой вопрос интересует» выглядит лучше, чем окончания Whisper, но буквального эталона нет. |
| small | Начало «Меня интересует Пух Варшаву»: ключевая фраза о туре искажена. Пунктуация слабее. Остальной вопрос про маму/программу различим. |
| medium | Начало «Меня интересует в Варшаву»: пропущено «тур». Фраза про программу сохранена с «с», окончание неровное. |
| turbo | Сохранил «тур в Варшаву» и «не быть с программой». Окончание «вот такого просто интересует» неровное. На этой фразе точнее Parakeet. |

Короткая запись всеми моделями передана как вопрос «Здравствуйте, есть ли у вас туры в Италию?» с различиями только в пунктуации. У каждого движка все три текста на каждом файле совпали, тишина не породила выдуманного текста. Полные расшифровки и результаты сохранены в частных артефактах опыта вне Git, без исходных CDN-ссылок и секретов.

Нет пословного подтверждённого эталона, поэтому WER и процент точности не вычислялись. Два коротких файла не дают общей оценки русского языка. Номера телефонов, даты, имена, шум, акценты, длинные записи, нагрузка от нескольких клиентов и GPU не испытывались. Измеренные ошибки не нужно «исправлять» добавлением подсказки с ожидаемым ответом — это исказит сравнение.
