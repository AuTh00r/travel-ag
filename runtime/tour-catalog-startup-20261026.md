# Новые туры и запуск после простоя

Дата:2026-10-26. Статус: выложено и проверено после отдельного «деплой».

## Симптом и проверенные причины

Владелец сообщил, что добавленные туры не появились в ответах. Read-only Drive
возвращает8документов; сохранённый рабочий каталог содержит6туров. Экспорт новых
DOCX «Белосток» и «Альпийский флирт» не содержит ни URL, ни строки бронирования.
build_snapshot намеренно исключал их по прежнему FR-3 AC2. Воркер при этом
работал:26октября сообщения skipped_no_booking повторялись примерно каждые300с.
Владелец подтвердил, что речь об этих турах. Текущее уточнение отменяет исключение.

Автозапуск отсутствующим не оказался: RestartTravelBot имеет BootTrigger и
Password-logon; последнее выполнение26октября10:44:30Минск успешно, код0.
Cloudflared настроен Start=2, FailureActions содержит restart через20с. Часть
опросов SCM/CIM текущему пользователю недоступна; доступные schtasks XML и
конкретные значения реестра прочитаны без изменения прав. BIOS/возврат питания
не проверены; причины времени физического включения машины не установлены.

Найден отдельный дефект _initial_tour_sync: ошибка Google оставляла DOCX, хотя
последний snapshot уже прочитан. Последующие unchanged-тику не публиковали
его в память. Это воспроизведённый дефект, но не причина пропуска двух новых
туров сегодня:26октября10:45:04Минск опубликован snapshot35698символов.
24октября ошибки tour_sync включали DNS oauth2.googleapis.com; это сетевые ошибки,
не доказательство отсутствия автозапуска.

## Исправление и границы

Документ без URL бронирования включается с booking_url=""; подтверждённая
ссылка программы сохраняется. Пустые документы пропускаются. Приоритет
документ → прежний ID → существующий seed и проверки просадки сохранены.
Промпт не требует выдумывать URL; справка доступна, оформление без ссылки
передаётся менеджеру. При начальном отказе/исключении публикуется last-good,
без перезаписи и уведомления. Unchanged согласует память только при расхождении;
выключенный worker не обращается к Drive.
