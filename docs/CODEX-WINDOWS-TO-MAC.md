# Перенос Codex, инструментов и проектов с Windows на Mac

Дата проверки исходного ноутбука: **4 ноября 2026 года**.

Этот гайд составлен для Windows-пользователя `AUTHOR` и текущего окружения Codex. Он объясняет, какие файлы сохранить, куда положить их на Mac, что настроить заново и как проверить результат. Команды ниже — инструкция для самостоятельного выполнения: при подготовке гайда резервные копии не создавались, приложения не закрывались, зависимости не устанавливались.

**Рабочий порядок: полная резервная копия → установка приложений на Mac → перенос проектов → восстановление настроек → проверка инструментов → отдельная проверка истории.** Исходный ноутбук и резервную копию сохраняй до завершения проверок.

Важное ограничение: `travel-agent-bot` содержит Windows-зависимый код обработки story/video. Перенести файлы можно сейчас; для работы этой функции на Mac потребуется отдельная правка кода. Этот гайд её не выполняет.

**Перенос через Git:** после публикации проверенного снимка разработки код,
тесты, спеки и документацию можно получить на Mac через `git clone`.
Полную файловую копию сохраняй как страховку. `.env`, credentials, рабочие БД,
модели и профиль Codex переносятся отдельно; они не входят в публичный снимок.
Инвентарь ниже описывает исходное состояние до уборки и сохранения в Git.

## 2. Карта Windows → Mac

`~` на Mac означает домашний каталог текущего пользователя: `/Users/<имя-на-Mac>`. Имя пользователя на Mac не обязано быть `AUTHOR`.

| Исходник Windows | Рабочее место на Mac | Как переносить |
| --- | --- | --- |
| `C:\Users\AUTHOR\.codex\config.toml` | `~/.codex/config.toml` | Адаптировать в копии и только затем применять |
| `C:\Users\AUTHOR\.codex\AGENTS.md` | `~/.codex/AGENTS.md` | Перенести; проверить абсолютные пути внутри |
| `C:\Users\AUTHOR\.agents\skills` | `~/.agents/skills` | Перенести пользовательские скиллы |
| `C:\Users\AUTHOR\.codex\skills` | Сначала отдельная копия, затем нужные пользовательские скиллы в `~/.agents/skills` | Не заменять встроенную `.system`, не перезаписывать одноимённые скиллы |
| `C:\Users\AUTHOR\.codex\rules` | `~/.codex/rules` | Проверить синтаксис и Windows-команды |
| `C:\Users\AUTHOR\.codex\hooks.json` и `hooks` | `~/.codex/hooks.json` и `~/.codex/hooks` | Включать после проверки путей и команд |
| `D:\projects\travel-agent-bot` | `~/projects/travel-agent-bot` | Полная файловая копия с `.git`, данными и скрытыми файлами |
| Остальные папки `D:\projects` | `~/projects/<имя>` | Полная файловая копия |
| `Documents\Codex\2026-08-01\x` | `~/projects/codex-2026-08-01-x` | Предлагаемое новое имя, чтобы не потерять происхождение |
| `Documents\Codex\2026-08-10\https-mooon-by-afisha-events-chelovek` | `~/projects/https-mooon-by-afisha-events-chelovek` | Полная копия |
| `Documents\ChatGPT\батарея` | `~/projects/батарея` | Полная копия |
| История, память, базы `.codex` | Полная резервная копия; отдельный пробный профиль | См. раздел 11; автоматический импорт не гарантирован |
| `.venv`, `node_modules`, Windows `.exe` | Новые окружения и зависимости для Mac | Пересоздать, старые версии не запускать |

Пути проектов в таблице — предлагаемые целевые пути. При выборе других каталогов используй их последовательно в конфигурации, `.env` и командах.

## 4. Подготовка Windows

### 4.1. Сначала сохранить инвентарь

Пока Codex ещё открыт:

1. Сохрани открытые редактором файлы.
2. Сфотографируй или запиши список проектов, установленных плагинов, подключений и расписаний. Не включай в снимки ключи и токены.
3. Для каждого важного чата сохрани краткую передачу контекста: что сделано, текущая задача, решения, непроверенное, пути к файлам. Положи её рядом с проектом, если нужно продолжать работу независимо от импорта истории.
4. Проверь, нет ли работы в отдельных worktree. Для каждого Git-проекта выполни:

```powershell
git -C 'D:\projects\travel-agent-bot' worktree list
git -C 'D:\projects\travel-agent-bot' status --short
```

Если worktree расположен вне копируемых папок, сохрани и его каталог. Файл `.git` внутри worktree может ссылаться на основной репозиторий абсолютным Windows-путём; такая связь требует восстановления на Mac. У текущего основного `travel-agent-bot` `.git` является каталогом.

Если `git status` пишет о недоступном глобальном ignore-файле, это отдельная проблема прав доступа Windows. Не считай предупреждение доказательством чистого дерева. Для проверки отслеживаемых изменений без обращения к глобальному списку можно выполнить:

```powershell
git -C 'D:\projects\travel-agent-bot' -c core.excludesFile=.git/info/exclude status --short --untracked-files=no
```

Последняя команда не перечисляет новые файлы. Полная файловая копия нужна независимо от её результата.

### 4.2. Сохранить версии Python-пакетов

Основное окружение проекта на Windows использует Python **3.12.13**. Большинство зависимостей в `requirements.txt` указаны через `>=`, поэтому новая установка может получить другие версии.

Из PowerShell:

```powershell
Set-Location 'D:\projects\travel-agent-bot'
& '.\.venv\Scripts\python.exe' --version
& '.\.venv\Scripts\python.exe' -m pip list --format=freeze |
    Set-Content -LiteralPath '.\windows-package-versions.txt' -Encoding utf8
```

Это инвентарь версий, а не готовый Mac lock-файл. Не устанавливай его целиком без просмотра: некоторые пакеты могут зависеть от Windows. Здесь используется `pip list`, чтобы не выводить URL источников установки, которые могут встречаться в `pip freeze`.

Если GigaAM установлен в отдельном окружении, аналогично сохрани список пакетов из его интерпретатора. Путь возьми из своей настройки `VOICE_PYTHON_EXECUTABLE`; значение ключей в чат отправлять не нужно.

### 4.3. Остановить запись данных

Перед копированием:

1. Заверши задачи Codex и останови его фоновые команды штатно.
2. Закрой Codex, CLI и IDE-подключения, использующие этот же профиль.
3. Если локальный бот запущен, останови его штатно, чтобы он не писал в `data/*.db`.
4. Не запускай приложения до завершения копирования.

Команду копирования запускай в **отдельном PowerShell вне Codex**. Встроенный терминал закрываемого приложения для этого не подходит. Не завершай MCP-процессы вручную через `kill`.

## 5. Полная резервная копия

### 5.1. Куда сохранять

Используй внешний носитель или защищённый канал передачи. Копия содержит историю, ключи, `.env`, учётные данные и бизнес-данные. Она не предназначена для публичного Git, открытых облачных ссылок и отправки в чат.

Ниже `E:\CodexMigration-2026-11-04` — **пример каталога на внешнем носителе**. Перед запуском замени `E:` на реальную букву своего диска. Команда специально требует новый каталог, чтобы не смешивать разные резервные копии.

### 5.2. Копирование в отдельном PowerShell

Следующий блок копирует профиль, скиллы, все четыре проекта из `D:\projects` и три дополнительных найденных проекта. Источники не удаляются. Ключи `/MIR`, `/PURGE`, `/MOVE` не используются.

```powershell
$ErrorActionPreference = 'Stop'
$migrationBackup = 'E:\CodexMigration-2026-11-04'

if (Test-Path -LiteralPath $migrationBackup) {
    throw 'Каталог копии уже существует. Укажи новое имя, чтобы не смешивать копии.'
}

$migrationCopies = @(
    @{ Source = 'C:\Users\AUTHOR\.codex'; Target = 'codex-home' },
    @{ Source = 'C:\Users\AUTHOR\.agents'; Target = 'agents-home' },
    @{ Source = 'D:\projects'; Target = 'projects' },
    @{ Source = 'C:\Users\AUTHOR\Documents\Codex\2026-08-01\x'; Target = 'extra-projects\codex-2026-08-01-x' },
    @{ Source = 'C:\Users\AUTHOR\Documents\Codex\2026-08-10\https-mooon-by-afisha-events-chelovek'; Target = 'extra-projects\https-mooon-by-afisha-events-chelovek' },
    @{ Source = 'C:\Users\AUTHOR\Documents\ChatGPT\батарея'; Target = 'extra-projects\батарея' }
)

foreach ($migrationItem in $migrationCopies) {
    if (-not (Test-Path -LiteralPath $migrationItem.Source -PathType Container)) {
        throw "Источник не найден: $($migrationItem.Source)"
    }
}

New-Item -ItemType Directory -Path $migrationBackup | Out-Null

foreach ($migrationItem in $migrationCopies) {
    $migrationTarget = Join-Path $migrationBackup $migrationItem.Target
    & robocopy $migrationItem.Source $migrationTarget /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ /SL
    $migrationCopyCode = $LASTEXITCODE
    if ($migrationCopyCode -ge 8) {
        throw "Ошибка robocopy ($migrationCopyCode): $($migrationItem.Source). Копия не завершена."
    }
    Write-Host "Скопировано: $($migrationItem.Target); код robocopy: $migrationCopyCode"
}

Write-Host "Копирование завершено: $migrationBackup"
```

У `robocopy` коды ниже 8 не означают обычную фатальную ошибку копирования, но сводку пропущенных файлов и расхождений всё равно нужно просмотреть. При исключении скрипт останавливается: не продолжай восстановление из неполной копии.

`/XJ` исключает junctions, `/SL` копирует символические ссылки как ссылки. Это предотвращает обход произвольных связанных каталогов, но **не сохраняет автоматически содержимое внешних целей ссылок**. Если копирование ссылок не поддерживается носителем или правами пользователя, нужно отдельно сохранить их реальные каталоги и потом восстановить ссылки на Mac. На проверенном верхнем уровне каталогов пользовательских скиллов ссылки не обнаружены; вложенные деревья целиком на ссылки не аудировались.

- Другие локальные данные, на которые ссылаются `.env`, скиллы, hooks и конфиги.

## 8. Настройки Codex

### 8.1. Сначала сохранить новый Mac-профиль

Закрой Codex и другие клиенты, использующие профиль. Через Finder скопируй `~/.codex` в отдельный каталог, например `~/MigrationBackup/codex-mac-before-import`. Если такой каталог уже есть, выбери другое имя.

Не заменяй новый профиль целиком без этой копии. Новый вход и Mac-компоненты имеют собственное состояние.

### 8.2. Основной конфиг

Исходник:

```text
~/MigrationBackup/CodexMigration-2026-11-04/codex-home/config.toml
```

Рабочий файл:

```text
~/.codex/config.toml
```

Пользовательский конфиг и проектный `.codex/config.toml` — разные слои. Проектные файлы тоже нужно проверить, если они есть в других проектах. [Документация OpenAI о конфигурации](https://developers.openai.com/codex/config-basic/).

Открой Windows-конфиг в локальном редакторе, рядом с новым Mac-конфигом. Перенеси нужные настройки модели, поведения, MCP и плагинов **после адаптации**.

| Windows-значение или конструкция | Что проверить на Mac |
| --- | --- |
| `C:\Users\AUTHOR\...` | Новый `/Users/<имя>/...` |
| `D:\projects\...` | Новый `/Users/<имя>/projects/...` |
| `node.exe`, `python.exe`, `node_repl.exe` | Реальный Mac-интерпретатор или компонент, поставляемый Mac-версией приложения |
| `cmd.exe`, `.cmd`, `.bat`, `powershell.exe` | Наличие подходящей реализации команды; механической замены расширения недостаточно |
| `cwd`, `args`, файловые источники marketplace | Каталог должен существовать на Mac |
| Ключи таблиц `[projects."..."]` | Новый абсолютный путь и актуальные настройки доверия |
| Windows sandbox и машинные разрешения | Настройки для текущей Mac-установки |
| Путь к Python/Node в переменных окружения | Результат `command -v`, доступный также приложению |

Не делай глобальную замену `\\` на `/` во всех файлах: обратный слеш может быть частью TOML-экранирования, регулярного выражения или текста. Редактируй конкретные поля.

Не полагайся на раскрытие `~`, `$HOME` или `%USERPROFILE%` внутри произвольного TOML-поля. Там, где документация поля не обещает раскрытия, указывай полный проверенный абсолютный путь.

Конфиг может содержать токены или чувствительные переменные. Не выкладывай его целиком и не добавляй в общий Git-репозиторий.

### 8.3. Как найти оставшиеся Windows-пути

В локальном редакторе выполни поиск по **выбранным текстовым настройкам**, а не по всей истории:

```text
C:\
D:\
C:/
D:/
AUTHOR
.exe
.cmd
.ps1
```

Проверь `config.toml`, `AGENTS.md`, `hooks.json`, собственные скиллы и `.env` проекта. Поиск в `.env` делай локально без публикации результатов. Не запускай замену по SQLite, архивам, истории сессий и встроенным файлам плагинов.

## 9. Скиллы, правила и hooks

### 9.1. Глобальные инструкции

Скопируй адаптированный `codex-home/AGENTS.md` в `~/.codex/AGENTS.md`, сохранив прежний Mac-файл отдельно, если он уже был.

Внутри могут быть ссылки на глобальный каталог AGGG4, скрипты, другие инструменты и диски Windows. Сам текст правила не переносит файлы, на которые оно ссылается. Если нужного скрипта нет, восстанови его источник или отметь правило как требующее настройки; не выдумывай рабочий путь.

### 9.2. Пользовательские скиллы

Основное официальное расположение пользовательских скиллов — `~/.agents/skills`; проектных — `.agents/skills` внутри репозитория. Скилл переносится всей папкой: `SKILL.md`, `scripts`, `references`, `assets`, `agents`, если они есть. [Документация OpenAI о скиллах](https://developers.openai.com/codex/skills/).

Порядок:

1. Сохрани текущую `~/.agents` на Mac, если она уже содержит твою работу.
2. Перенеси `agents-home/skills` в `~/.agents/skills`, не перезаписывая одноимённые каталоги без сравнения.
3. Отдельно сравни скиллы из `codex-home/skills` с уже перенесёнными.
4. Перенеси уникальные пользовательские скиллы из старого расположения в `~/.agents/skills`.
5. При совпадении имени выбери нужную версию по содержимому. Не объединяй автоматически разные `SKILL.md` и скрипты.
6. Встроенную папку `.system` и скиллы из кеша плагинов должна поставлять новая установка или соответствующий плагин.
7. Исправь абсолютные пути и платформенные команды в собственных скиллах.

Старую `.codex/skills` всё равно сохраняй в резервной копии. Наличие этого каталога в прежней установке не означает, что новая версия будет обнаруживать его так же.

После переноса проверь список скиллов в приложении или через `/skills` в CLI. Перезапусти клиент, если изменения не появились.

### 9.3. Hooks и правила

Найдены:

```text
codex-home/hooks.json
codex-home/hooks/aggg4-agent-gates.mjs
codex-home/hooks/aggg4-doc-drift.mjs
codex-home/rules/default.rules
```

Скрипты `.mjs` скопируй в `~/.codex/hooks`, правила — в `~/.codex/rules`. **Конфигурацию `hooks.json` применяй после просмотра команд**, чтобы первый запуск не пытался выполнить старый Windows-путь.

Проверь, что Node.js доступен процессу Codex, пути указывают на Mac-файлы, а правила учитывают используемые на Mac команды. Проверка синтаксиса для найденных скриптов:

```bash
node --check "$HOME/.codex/hooks/aggg4-agent-gates.mjs"
node --check "$HOME/.codex/hooks/aggg4-doc-drift.mjs"
```

Это проверяет синтаксис JavaScript, но не подтверждает работу самого hook. Поведение проверяй штатным безопасным сценарием из его документации; не отключай защиту ради успешного запуска.

## 10. MCP и плагины

### 10.1. Найденные MCP

В текущем пользовательском конфиге есть:

```text
node_repl
context7
gh_grep
playwright
openaiDeveloperDocs
```

| MCP | Что делать |
| --- | --- |
| `node_repl` | Старый путь ведёт к `node_repl.exe`. Не переносить этот исполняемый файл как Mac-решение. Использовать компонент и настройку Mac-версии, если она его предоставляет; старую Windows-команду не включать |
| `context7` | Проверить тип соединения, адрес/команду и нужные переменные. Для HTTP не менять адрес только из-за смены ОС |
| `gh_grep` | Аналогично сверить исходную конфигурацию и выполнить запрос чтения |
| `playwright` | Найдена команда `npx`; нужен Node.js на Mac и браузеры, устанавливаемые подходящей версией Playwright. Windows-кеш браузеров не использовать |
| `openaiDeveloperDocs` | Сохранить подходящую конфигурацию соединения и проверить поиск документации |

Для каждого MCP прочитай поля `command`, `args`, `cwd`, `url`, названия переменных окружения. Не копируй только имя: оно не описывает способ запуска сервера.

### 10.2. Проверка через CLI

Если CLI установлен и использует нужный профиль:

```bash
codex mcp list
```

Для сервера с OAuth, когда нужен новый вход:

```bash
codex mcp login ИМЯ_СЕРВЕРА
```

Вместо `ИМЯ_СЕРВЕРА` подставь реальное имя из списка. Не все серверы поддерживают OAuth. После входа или изменения конфигурации начни новый чат и выполни простой запрос чтения к каждому нужному MCP. Наличие записи в списке ещё не доказывает успешный вызов инструмента. [Официальные команды MCP](https://developers.openai.com/codex/mcp/).

Если терминал видит `node`, а приложение нет, сверяй окружение и путь запуска приложения. Настройки оболочки и графического клиента могут отличаться; используй проверенный абсолютный путь в полях, где это поддерживается.

### 10.3. Плагины и подключения

`plugins/` включает кеши и состояние конкретной установки. Полную копию сохраняем, но в рабочем Mac-профиле предпочтительно установить нужные плагины через интерфейс приложения и восстановить доступ к сервисам.

Проверь отдельно:

- список установленных плагинов;
- источники marketplace, особенно локальные Windows-пути;
- подключённые GitHub, Google Drive и другие реально используемые сервисы;
- разрешения и доступность в том же workspace.

Часть подключений может оказаться доступной после входа в аккаунт; это нужно проверить, а не считать гарантией. Для собственных плагинов сохрани исходники и их зависимости, а не только кеш внутри `.codex/plugins/cache`.

В исходной конфигурации найдены такие локальные источники:

| Источник Windows | Действие на Mac |
| --- | --- |
| `C:\Users\AUTHOR\.codex\.tmp\bundled-marketplaces\openai-bundled` | Это источник внутри старого профиля. Используй источник, предоставленный новой установкой; Windows-путь не активируй |
| `C:\Users\AUTHOR\.cache\codex-runtimes\codex-primary-runtime\plugins\openai-primary-runtime` | Этот каталог находится вне `.codex`. Его компоненты должна предоставить Mac-установка; не подменяй их Windows-runtime |

Эти пути объясняют, почему даже полная копия `.codex` не является готовой установкой всех инструментов для другой ОС.

### 10.4. Управление компьютером и браузером

Windows-компоненты computer-use и браузерные профили не следует переносить как готовые Mac-драйверы. Используй компоненты новой установки. Разрешения на управление компьютером, доступ к экрану и браузеру выдай через штатные запросы macOS по мере необходимости.

Не копируй браузерные cookie как замену входа. В нужные сайты войди заново.

### 11.1. Что нужно сохранить обязательно

Сохраняется **весь закрытый профиль `codex-home`**, включая:

```text

state_5.sqlite
thread_history_1.sqlite
memories_1.sqlite
goals_1.sqlite
```

Если после закрытия рядом с базами остались `-wal`/`-shm`, сохраняй комплект, не удаляя файлы вручную. Базы не нужно открывать в текстовом редакторе.

Официальная документация подтверждает хранение локального состояния в `CODEX_HOME`, но не даёт здесь гарантии полного переноса истории и интерфейсного состояния Windows → Mac. [Расположение состояния Codex](https://learn.chatgpt.com/docs/config-file/config-advanced#config-and-state-locations).

### 11.2. Почему нельзя просто вставить одну базу

История, индекс, метаданные, вложения и пути могут зависеть друг от друга. Замена одной SQLite-базы в работающем Mac-профиле способна смешать состояние разных установок. Наличие сессий в каталоге не гарантирует, что они появятся в боковой панели.

Не выполняй SQL-обновления для массовой замены Windows-путей и не склеивай базы вручную. Формат внутреннего состояния может отличаться между версиями.

### 11.3. Изолированная проба для CLI

Если важно попробовать чтение старых сессий, используй **отдельную копию профиля**, не основной `~/.codex`.

Порядок:

1. Скопируй `codex-home` из резервной копии в новый каталог `~/MigrationBackup/codex-history-trial`. Исходную копию не изменяй.
2. Сохрани в пробном каталоге базы и файлы сессий комплектом.
3. До запуска через Finder вынеси из пробного каталога старые `auth.json`, `auth.lock`, `cap_sid`, `installation_id`, lock-каталоги, Windows-кеши и sandbox-файлы в отдельный каталог. Не переноси их в основной Mac-профиль. Это не список всех возможных машинных файлов: при новых именах нужна проверка их назначения.
4. Сохрани исходный пробный `config.toml` отдельно, а в пробный профиль положи уже адаптированный Mac-конфиг.
5. Аналогично используй адаптированные hooks или отложи их подключение до проверки; не запускай старые команды автоматически.
6. При установленном CLI запусти его с отдельным `CODEX_HOME`:

```bash
CODEX_HOME="$HOME/MigrationBackup/codex-history-trial" codex
```

Выполни новый вход, если он потребуется. Через `/resume` проверь, видны ли нужные сессии. Не отправляй рабочую задачу в старый чат, пока его текущая папка и инструменты не проверены.

Список сессий может зависеть от текущей рабочей папки. У старых чатов сохранён Windows-путь, поэтому пустой список сам по себе не доказывает неудачный перенос. Сначала сверь `codex resume --help` своей версии, затем при поддержке нужных флагов используй:

```bash
CODEX_HOME="$HOME/MigrationBackup/codex-history-trial" codex resume --all --cd "$HOME/projects/travel-agent-bot"
```

`--all` расширяет выбор сессий за пределы текущей папки, `--cd` задаёт реальный Mac-каталог для продолжения. Для чата другого проекта укажи каталог именно того проекта. [Справочник CLI](https://developers.openai.com/codex/cli/reference/).

Такое задание переменной действует для конкретного CLI-процесса. **Оно не переключает автоматически уже запущенное графическое приложение.** Успешное чтение CLI не доказывает восстановление боковой панели приложения.

Если сессии не появились, сохрани пробную копию и вернись к рабочему Mac-профилю. Не считай историю потерянной, пока исходный профиль сохранён. Продолжить проект можно из его файлов, спек и подготовленного описания контекста.

### 11.4. Интерфейс, вкладки и память

Закрепления, расположение проектов, вкладки и старые абсолютные пути могут потребовать ручного восстановления. `.codex-global-state.json` сохрани как материал для сверки, а не как переносимый набор пользовательских настроек.

Наличие `memories_1.sqlite` не означает, что все виды памяти хранятся только там. Память внешнего сервиса, например MemoryMCP, нужно переносить по правилам этого сервиса.

## 12. Автоматизации

Сначала раздели локальные и серверные расписания. Каталог `automations/` сохраняется в копии, но его наличие не определяет место исполнения всех автоматизаций.

На Mac открой список автоматизаций и для каждой проверь:

| Поле | Проверка |

### 13.2. Пересоздание основного Python-окружения

Перейди в Mac-копию проекта. Если туда попала Windows `.venv`, **перемести только её** в отдельную папку резервной копии через Finder. Проверь полный путь перед перемещением. Не запускай Windows-интерпретатор и не создавай новое окружение поверх старого.

Когда `.venv` отсутствует:

```bash
cd "$HOME/projects/travel-agent-bot"
python3.12 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
python -m pip check
```

На Mac активация — `.venv/bin/activate`, а интерпретатор — `.venv/bin/python`; Windows-путь `.venv\Scripts\python.exe` не подходит.

Python Playwright и браузерный MCP Playwright — разные установки. Если тестам Python нужен Chromium, установи браузер из того же основного окружения:

```bash
python -m playwright install chromium
```

Эта команда скачивает браузер для версии Python-пакета в `.venv`. Она не настраивает автоматически Node.js MCP и не требует переносить Windows-кеш браузера. Если конкретный тест или MCP требует другой движок, используй его документированные требования.

Если установка завершилась ошибкой, исправь конкретную зависимость до запуска бота. Сверь версии с `windows-package-versions.txt`, особенно если установка подтянула более новые пакеты. Не уменьшай проверки проекта ради прохождения установки.

### 13.3. Конфигурация и данные

В рабочей Mac-копии `.env` проверь:

- пути к `credentials` и локальным базам;
- каталоги моделей и внешних данных;
- `VOICE_PYTHON_EXECUTABLE` и `VOICE_MODEL_DIR`;
- обращения к Windows-командам и дискам;
- используется ли та же бизнес-интеграция, что у действующего бота.

Имена файлов секретов можно сверять, содержимое в логи выводить не нужно. Сохрани исходный Windows `.env` в защищённой резервной копии.

Копия `.env` с действующими ключами может подключить Mac к тем же реальным интеграциям. Запуск приложения способен запустить фоновые обработчики и доставку накопленных сообщений. Для локальной проверки сначала используй тестовые подключения и копию данных; не запускай второй рабочий экземпляр на тех же интеграциях без согласованного переключения.

### 13.4. GigaAM — отдельное окружение

Проектная документация требует отдельное окружение для `requirements-gigaam.txt`. Не устанавливай его в основную `.venv` бота.

На момент проверки файл фиксирует `onnx-asr==0.12.0`, `onnxruntime==1.23.2`, `numpy==2.2.6`, `av==16.1.0`. Доступность подходящих пакетов для архитектуры твоего Mac нужно проверить при установке; Windows-бинарники не являются заменой.

Вариант структуры на Mac:

```text
~/projects/travel-agent-bot/.venv/           основное окружение
~/projects/travel-agent-bot/.venv-gigaam/    отдельное окружение распознавания
~/models/gigaam/                           файлы модели
```

Если совместимость зависимостей с Mac подтверждена и каталог `.venv-gigaam` ещё не существует:

```bash
cd "$HOME/projects/travel-agent-bot"
python3.12 -m venv .venv-gigaam
.venv-gigaam/bin/python -m pip install -r requirements-gigaam.txt
.venv-gigaam/bin/python -m pip check
```

В `.env` укажи **свои реальные абсолютные пути**, например:

```dotenv
VOICE_PYTHON_EXECUTABLE=/Users/YOUR_MAC_USER/projects/travel-agent-bot/.venv-gigaam/bin/python
VOICE_MODEL_DIR=/Users/YOUR_MAC_USER/models/gigaam
```

`YOUR_MAC_USER` нужно заменить; эти строки не являются готовыми значениями для любого Mac. Файлы моделей сохрани из фактического Windows-каталога `VOICE_MODEL_DIR` или восстанови из проверенного источника с контролем хешей. Если каталог лежит вне сохранённых проектов, основной блок резервного копирования его не захватит.

Успешный `pip install` ещё не подтверждает корректную работу голосового worker. Сверяй `docs/DEVELOPMENT.md` и `runtime/gigaam-voice-integration.md`, затем проверь голосовой сценарий отдельно.

### 13.5. Windows-зависимые функции

Найдены `deploy.ps1`, `watchdog.cmd`, PowerShell-скрипты в `scripts/` и `src/services/`.

Особенно важно: `src/services/story_media.py` использует `decode_story_media.ps1` и явно запускает:

```text
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
```

На Mac этого пути нет. Установка PowerShell для Mac сама по себе не исправляет жёстко заданный Windows-путь и не доказывает переносимость декодера.

Для обработки story/video требуется отдельная задача: изучить декодер, выбрать переносимую реализацию, обновить спецификацию, код и проверки. До этого нельзя заявлять полную работоспособность всего бота на Mac. Windows-специфичные проверки тоже могут потребовать адаптации.

`deploy.ps1` и `watchdog.cmd` не запускай как часть восстановления. Они относятся к эксплуатации и развёртыванию; перенос среды разработки не требует изменения действующего сервера.

### 13.6. Проверки и локальный запуск

Из основной `.venv`:

```bash
cd "$HOME/projects/travel-agent-bot"
source .venv/bin/activate
python -m pytest tests/ -q
python -m ruff check src tests
python -m black --check src tests
```

В текущем `conftest.py` есть изоляция SQLite и запрет реальных HTTP-запросов через httpx. Тем не менее это проверка текущего набора тестов, а не обещание отсутствия любой внешней активности у произвольных новых проверок. Не запускай live/probe/deploy-скрипты вместо обычного pytest.

Если тесты падают на Mac, зафиксируй конкретную ошибку, версию Python и пакеты. Отдельно отличай недостающую зависимость, изменившуюся версию пакета и Windows-зависимый код. Не исправляй ситуацию удалением тестов или отключением сетевой изоляции.

**Только после настройки тестовых интеграций и проверки фоновых действий** можно запустить локальный сервер:

```bash
python -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

В другом окне Terminal:

```bash
curl --fail http://127.0.0.1:8000/health
```

Остановка сервера — `Ctrl+C` в его терминале. Успешный `/health` подтверждает доступность этого маршрута, но не исправность story/video, голосового worker и всех внешних каналов.

## 14. Ключи, SSH и внешние данные

### 14.1. Вход в Codex и OAuth

На Mac войди заново. `auth.json` содержит токены; полная резервная копия его сохраняет как чувствительные данные, но для обычного восстановления он не нужен. Секреты могут находиться и в хранилище ОС, поэтому копия одной `.codex` не гарантирует перенос всех авторизаций. [Документация OpenAI о хранении учётных данных](https://learn.chatgpt.com/docs/auth#credential-storage).

### 14.2. SSH

Если используешь SSH, проверь на Windows `C:\Users\AUTHOR\.ssh`. Наличие и содержимое этого каталога в текущем аудите не подтверждены.

Предпочтительный вариант — создать отдельный ключ для Mac и добавить его на нужные серверы с разрешения владельца. Если требуется перенос существующего ключа, передавай его только защищённо и не заменяй уже имеющиеся Mac-ключи.

На Mac:

```bash
mkdir -p "$HOME/.ssh"
chmod 700 "$HOME/.ssh"
```

Для конкретного перенесённого приватного ключа задай права `600`, подставив его действительное имя:

```bash
chmod 600 "$HOME/.ssh/ИМЯ_ПРИВАТНОГО_КЛЮЧА"
```

В `~/.ssh/config` проверь `IdentityFile`, `Include`, `ProxyCommand` и вызовы `.exe`. Например, если там вызывается `cloudflared.exe`, потребуется Mac-версия инструмента и адаптированная команда. Это условный пример, а не подтверждение содержимого твоего SSH-конфига.

### 14.3. Git

Проверь собственные значения на Mac:

```bash
git config --global --get user.name
git config --global --get user.email
git config --global --get core.excludesFile
git config --global --get credential.helper
```

Отсутствующее значение может завершить отдельную команду ненулевым кодом: это означает, что оно не задано. Не печатай всю глобальную конфигурацию в публичные логи — там могут быть чувствительные адреса и настройки.

`C:\Users\AUTHOR\.gitconfig` можно сохранить отдельно, если он есть. Переноси нужные поля, а не весь файл вслепую: credential helper, SSH-команды, пути к ignore-файлам и редактору могут быть Windows-специфичными. Доступ к GitHub через плагин и доступ `git` по SSH/HTTPS проверяются отдельно.

### 14.4. Серверы и внешние хранилища

Этот гайд переносит ноутбучное окружение. Он не переносит автоматически:

- данные действующего сервера бота;
- внешнюю БД или облачный bucket;
- Google Drive, почту и другие сервисы в локальные файлы;
- независимый vault MemoryMCP;
- модели и кеши в каталогах, не вошедших в копию;
- Windows-планировщик задач и другие системные службы.

У проекта есть документация SSH и развёртывания в `docs/`. Восстановить доступ к существующему серверу — отдельный шаг; переносить production на Mac ради работы с кодом не нужно.

| Проверка | Что считается подтверждением | Если не прошло |

## 16. Проблемы и восстановление

| Симптом | Вероятная причина | Что делать |
| --- | --- | --- |
| `command not found: codex` | CLI не установлен или не в PATH | Использовать интерфейс приложения либо установить/настроить CLI отдельно |
| `node` работает в Terminal, но MCP не стартует | У приложения другое окружение | Проверить команду и доступный приложению абсолютный путь |
| `ENOENT`, `file not found`, путь с `C:` | Остался Windows-путь | Исправить соответствующее поле в копии настроек |
| Скиллы не видны | Неподдерживаемое расположение, конфликт имён, отсутствующий target ссылки | Проверить `~/.agents/skills`, `SKILL.md` и перезапустить клиент |
| Не открывается старый проект | Запись всё ещё указывает на Windows | Добавить реальный каталог Mac через интерфейс |
| В истории нет чатов | Не перенесён комплект состояния или клиент не поддерживает его чтение | Сохранить исходный профиль, проверять отдельно; не заменять базы по одной |
| SQLite locked или повреждение после копии | Источник продолжал работать или перенесён неполный комплект | Повторить полную копию после штатного закрытия |
| Python импортирует не те пакеты | Активировано другое окружение | Проверить `command -v python`, `python --version`, активацию `.venv` |
| Ошибка запуска `powershell.exe` | Жёсткая Windows-зависимость | Отдельная адаптация кода; перенос файлов её не исправляет |
| Повторяются фоновые действия | Одновременно работают два экземпляра/расписания | Остановить новый экземпляр и согласовать переключение |

Чтобы откатить настройки Mac: закрой Codex, сохрани неудачную попытку в отдельный каталог и верни собственную Mac-копию профиля, созданную до импорта. Не удаляй единственную Windows-копию и не заменяй её файлами, уже изменёнными на Mac.

Если неясно, какой профиль используется, сначала проверь `CODEX_HOME`, способ запуска клиента и фактический файл конфигурации. Не переключай несколько клиентов одновременно во время восстановления.
